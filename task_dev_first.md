# Backlog produit : Djuma orienté développeur

## Objectif
Rendre Djuma prioritairement utile aux développeurs, avec un workflow centré sur les projets techniques, le suivi du temps, le focus de travail et l’intégration au monde du développement.

---

## Priorité 1 — Fondamentaux produit

- [ ] Ajouter un type de tâche spécifique pour les projets techniques : bug, feature, refactor, documentation, test, hotfix
- [ ] Ajouter un champ "Projet / Repository / Branche" sur chaque tâche
- [ ] Créer des projets avec plusieurs tâches liées entre elles
- [ ] Ajouter une vue "Backlog / En cours / Bloqué / Terminé" pour les tâches techniques
- [ ] Permettre de créer des sous-tâches techniques

## Priorité 2 — Suivi du temps

- [ ] Ajouter un minuteur par tâche avec démarrage/arrêt manuel
- [ ] Enregistrer le temps cumulé par tâche, par projet et par type
- [ ] Ajouter un historique de sessions de travail avec date, durée et statut
- [ ] Afficher des statistiques : temps total, temps par projet, temps en interruptions, tâches les plus longues
- [ ] Ajouter un indicateur de temps estimé vs temps réel

## Priorité 3 — Focus mode développeur

- [ ] Créer un mode "Focus développeur" avec blocage configurable des applications non autorisées
- [ ] Autoriser une liste blanche d’applications : IDE, terminal, navigateur de documentation, outils de développement
- [ ] Bloquer les distractions : réseaux sociaux, messageries, streaming, sites non utiles
- [ ] Ajouter un mode "Pause technique" et un mode "Snooze" plus intelligent
- [ ] Permettre de configurer le focus selon le type de tâche (code, débat, revue, debug)

## Priorité 4 — Workflow technique

- [ ] Intégrer des liens vers des tickets : GitHub, GitLab, Azure DevOps, Jira
- [ ] Ajouter la possibilité d’associer une tâche à un ticket existant ou une issue
- [ ] Ajouter le support de branche Git et afficher le contexte de travail actuel
- [ ] Permettre d’ouvrir directement le dépôt, la branche, le ticket ou le dossier du projet
- [ ] Ajouter un contexte technique visible sur chaque tâche : repo, branche, ticket, environnement

## Priorité 5 — Productivité et ergonomie

- [ ] Ajouter des raccourcis clavier pour créer, démarrer, terminer et valider une tâche
- [ ] Optimiser l’interface pour un usage "IDE-first" : navigation rapide, actions clavier, moins de clics
- [ ] Ajouter des filtres avancés : par projet, priorité, type, statut, temps passé
- [ ] Ajouter une vue compacte pour les tâches rapides et une vue détaillée pour les tâches longues
- [ ] Améliorer la vitesse de saisie et l’édition des tâches

## Priorité 6 — Analyse et pilotage

- [ ] Créer un tableau de bord pour suivre les tâches en cours, tâches bloquées et temps passé
- [ ] Ajouter un indicateur des tâches qui dépassent leur temps prévu
- [ ] Ajouter un système de blocage avec raison, notes de contexte et date de reprise
- [ ] Afficher les tâches critiques et les dépendances entre tâches
- [ ] Ajouter un résumé hebdomadaire de productivité

## Priorité 7 — Intégration avec l’écosystème de dev

- [ ] Intégrer VS Code / JetBrains pour ouvrir le fichier ou le projet associé
- [ ] Ajouter un bouton "Lancer test/build" depuis une tâche
- [ ] Ajouter un mode "Sprint" avec objectifs quotidiens ou hebdomadaires
- [ ] Préparer une version avec export de rapports / statistiques / CSV
- [ ] Préparer une intégration avancée avec outils de gestion de projet externes

---

## MVP recommandé pour la première version orientée développeur

- [ ] Type de tâche technique
- [ ] Projet + branche + ticket
- [ ] Minuteur de tâche
- [ ] Focus mode bloquant les distractions
- [ ] Dashboard simple de temps et tâches
- [ ] Raccourcis clavier essentiels
- [ ] Filtres et vues de projet

## Priorité d’implémentation

1. Projets techniques + tâches associées
2. Suivi du temps par tâche
3. Focus mode développeur
4. Intégration Git / ticket
5. Raccourcis clavier et fluidité
6. Dashboard analytique
7. Intégration IDE / tests / sprint

---

## Résumé
Le logiciel a déjà une bonne base en gestion de tâches et en mode focus, mais il doit devenir un outil centré sur le développeur en ajoutant les concepts qui structurent le travailtechnique : projet, branche, ticket, temps, blocage, focus, sprint et intégration avec l’écosystème de développement.
